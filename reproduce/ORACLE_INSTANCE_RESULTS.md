# GT instance 直接赋给 Uni3R Gaussian：完成结果

日期：2026-10-08。完整运行退出码 0，日志确认 `COMPLETED 18 pairs`。

## 实验范围

- 冻结官方 `2views.pth`，沿用原始 Uni3R forward，不训练、不做 target pose optimization。
- 公开 SIU3R ScanNet 数据中，与本地 Uni3R 测试场景重合的 `scene0689_00`、`scene0701_00`、`scene0702_02`。按压缩包较小选择，未按结果筛选。
- 每场景 6 组官方输入对，共 18 组；每组 4 个非输入目标视角。共 72 次新视角、36 次单源互渲染，每次均计算两种坐标处理。
- 标签按源像素直接赋给对应 Gaussian，使用完整实例 ID。评价不重新匹配 ID，不合并同类实例。
- 这三场景是诊断数据；不拿它们训练学生后再报告未见场景泛化。

## 如何理解

GT 标签贴到 Uni3R 预测的 Gaussian 后，在这些输入对的附近新视角上能够形成有意义的实例区域，值得进入学生可学习性验证。可视化中仍有椅子细结构、边界、遮挡和小物体错误。

不能据此判断几何已经全面可靠：去掉目标视角自身 Gaussians 后，互渲染分数明显降低；限制到 GT 可覆盖区域后仍有错误。三维厘米级误差也明显依赖坐标对齐。拟合源深度 Sim(3) 改善总体表面距离，却降低新视角 mask IoU，说明单一几何分数不能代替渲染和身份一致性评价。

两种模式都使用 GT 相机把模型坐标与评测坐标关联，并在已知目标相机下渲染。原约定使用第一输入相机及输入相机基线；Sim(3) 还使用输入 GT depth。因此这是带 GT 标签和评测几何的诊断，不是完全无位姿部署结果。点投影参照使用 z-buffer 和 3×3 footprint，与 Gaussian 渲染不同，不能当严格上界。

这不是训练后的实例性能，不是官方 ScanNet 3D AP，也不能直接与论文主表比较。只有三个按文件体积挑选的场景，且使用 SIU3R 的裁剪/帧选择，不能概括全部 Uni3R 场景。

## 产物与复现

- `outputs/instance_oracle/run/index.html`：全部源图、目标图和标签对照。
- `outputs/instance_oracle/run/diagnostic_examples.jpg`：三场景示例，包含最低分目标视角。
- `outputs/instance_oracle/run/aggregate.json`：总体及分场景聚合。
- 每组目录含 `metrics.json`、原坐标 Gaussian 属性和 ID 的 `gaussians_native.npz`、渲染标签/覆盖/深度 NPZ，以及 `instances_context_sim3.ply`。PLY 是带标签的中心点云，不是完整 Gaussian renderer 文件。
- `outputs/instance_oracle/overlap_data/provenance.json`：下载来源与校验；`pairs.json`：固定输入/目标选择。
- `outputs/instance_oracle/run/manifest.json`：模型与脚本版本信息。

运行命令：`UNI3R_GPU=0 bash reproduce/run_oracle_lifting.sh --resume`。脚本会校验既有运行配置与版本，防止把不同实验混在一起。验证过 RGB ID 解码、Sim(3)/相机投影、ID 交换惩罚、内参反投影四项数学测试；最终产物数量核对为 18 组指标/PLY、72 张新视角图和 36 张互渲染图。
